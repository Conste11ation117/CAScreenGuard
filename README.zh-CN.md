# 此软件如何编写？
*与DeepSeek v4.1 flash和Kimi Code、DeepSeek Harness、WorkBuddy共同构建。*

离开时让它盖住屏幕：只关显示器，不锁定 Windows 会话，不进入睡眠；最上层盖一层全屏遮罩，
输入正确的解锁密码才恢复。

遮罩以你自己的桌面壁纸打底并压暗，上方按 Windows 11 锁屏的比例显示时间与日期，中间是解锁密码卡片。
读不到壁纸时退回纯黑。桌面内容全程不会露出。

- 版本：V3.2.0
- 作者：@Conste11ation117
- 运行环境：Windows 10 / 11，Windows PowerShell 5.1（系统自带，不需要装任何东西）
- 许可：[MIT](LICENSE)
- 与 JetBrains 无关联；图标风格是对其图标体系的一次致敬

## 零、元定位
**在主机处于无人值守状态下，保持长流程的工作正常进行并保护您后台正在进行的工作和私密文件免于任何不可察觉的偷窥、窃取和破解手段。**

## 一、适用与不适用

适合：离开工位几分钟、公共或共享桌面、跑长任务时想遮住屏幕但不想让会话被系统锁掉。

不适合：真正需要保密的数据、防范有心人、防远程会话或其他账户，以及任何需要安全边界的场合。

它防的是路过的人随手看一眼，不防专门来翻电脑的人。它不锁定 Windows 会话，也不加密任何东西。

`Ctrl+Alt+Del` 不是缺口：那个界面上没有任何操作能让桌面露出来。注销和关机会结束会话（或重启），
桌面自始至终没出现过，标记文件会记下这件事；任务管理器能启动，但遮罩每 250 毫秒重新置顶并抢回焦点，
上面没有可点的目标。需要保密请用 Windows 锁屏（`Win+L`）加 BitLocker。

## 二、锁屏期间的操作

| 操作 | 行为 |
|---|---|
| 任意键 / 移动鼠标 | 点亮屏幕、露出密码框（桌面内容仍被挡着） |
| 解锁密码 + `Enter` | 解锁：遮罩渐隐约 0.7 秒，恢复屏幕、还原屏保设置，退出 |
| `Ctrl + Backspace`（`Ctrl + U` 同效） | 清空已输入内容 |
| `Esc` | 立刻再次熄屏，已输入内容保留 |
| 无操作 25 秒（可调） | 自动再次熄屏，已输入内容保留 |
| `Ctrl + Shift + Alt + E` | 打开「修改解锁密码」，需要授权码，改完仍是锁屏 |
| `Win` / `Alt+Tab` / `Alt+Esc` / `Ctrl+Esc` | 被吞掉，避免用开始菜单或任务切换缩略图看到桌面 |

## 三、界面上有什么

- 壁纸打底：启动时读取当前桌面壁纸（`SPI_GETDESKWALLPAPER`），按填充铺满整个虚拟桌面再压暗。
  纯色壁纸、幻灯片、文件损坏等读不到图的情况，静默退回纯黑，每次启动各自判断一次。
- 时间与日期：按 Win11 锁屏的实测比例排布（数字高 71 DIP、顶边距 162 DIP、两行间距 32 DIP），
  屏幕太矮会自动缩小。
- 卡片：圆角、深色，比周围再压一层，所以文字始终比背景清楚。密码框描边会显示聚焦、输错、封禁三种状态。
- 左上角：如果你装了配套的 [DeepSeek Harness 插件](https://github.com/Conste11ation117/dsh-get-session-status)，
  这里会显示 agent 是在跑还是在等你（详见[桥接层](docs/bridge.md)）。没装就不显示。
- 左下角：品牌标记与产品名。产品名用 JetBrains Mono 预先渲染成图片内嵌，用户不需要安装字体。
- 右下角：电量与网络。电池图标加百分比，充电时叠一个闪电，低于 15% 电量条转红；网络图标分别是
  Wi-Fi 弧线（按信号强度亮一到三格）、有线地球、无网斜杠地球。
- 手掌标记（标题左侧）用系统符号字体里的 Unicode 举手字形 U+270B。

壁纸本来就是解锁后任何人都能看到的那张图，不构成新的信息暴露。如果你介意，把桌面壁纸设成纯色，
程序会自动退回纯黑。

## 四、连错封禁

- 解锁密码连错 8 次：禁止继续输入，卡片下方显示「已禁止输入密码」与关机提示。
- 授权码连错 3 次：除红色警告外，窗口内全部输入禁用（输入框与确定按钮置灰，只留退出/取消）。
- 授权码输错不给任何提示：既不确认猜错，也不告诉剩余次数，避免被当成试错通道。

两种封禁力度不同：

| 发生位置 | 连错 3 次之后 |
|---|---|
| 「修改解锁密码」 | 本次运行内禁止，关掉重开恢复 |
| 「配置需要重建」 | 永久封禁：注册表与 `%APPDATA%` 各写一份，重启不解除，只有重新安装才清掉 |

后者按「配置被人动过，且三次拿不出授权码」处理。

## 五、密码、授权码与篡改检测

| | 解锁密码 | 授权码 |
|---|---|---|
| 用途 | 日常解锁 | 忘记解锁密码时唯一的凭据 |
| 长度 / 字符 | 至少 4 位，英文/数字/符号 | 至少 6 位，同规则 |
| 存储 | PBKDF2-SHA1，12 万次迭代 + 随机盐，只存哈希 | 同左 |
| 能否更改 | 可以（需通过授权码） | 安装时定版，之后不能改 |

配置文件 `.cascreenguard.config.json`（隐藏，与脚本同目录）内含一段 HMAC-SHA256 摘要，
摘要密钥不在配置里，存放在两处外部凭证：注册表 `HKCU\Software\CAScreenGuard` 与
`%APPDATA%\CAScreenGuard\store.json`。配置被删除或改动哪怕一个字节，下次启动就拒绝开锁并要求重建。

程序里没有任何人的密码。密码由安装向导当场收集、算成哈希后写入配置与外部凭证，
脚本、C# 源码和 exe 里都不存在密码字面值。

## 六、异常退出与日志

- 进入锁屏时写 `%LOCALAPPDATA%\CAScreenGuard\running.flag`，正常退出时删除。
- 下次启动若发现它还在，说明上次没有正常结束，会分两种情况提示：
  - 有崩溃日志（`crash-*.log`，自动只留最近 10 份）→ 程序自身出错，给出路径，请连同复现步骤反馈；
  - 没有崩溃日志 → 不是崩溃：可能是按了电源键、用 `Ctrl+Alt+Del` 注销或关机，或直接结束了进程。
    会提示你修改电脑密码、运行杀毒软件、检查物理环境安全，然后重新安装。
- `guard.log` 记录启动/退出、睡眠恢复、唤醒请求重发失败、界面线程异常，超过 64 KB 自动截断。
  里面不写用户名、机器名、路径和 PID，可以直接发出来排错。`crash-*.log` 才有 `user@machine` 和 PID，
  那是本机日志，不必外发。

## 七、安装与卸载

双击 `CAScreenGuard-Setup.exe`：

1. 欢迎页：程序简介、杀毒软件提示、界面语言选择（简体中文 / English），
   以及一条可选提示——如果你用 DeepSeek Harness，建议安装配套插件。
2. 安装页：安装位置（含「会装到…」实时预览）、解锁密码、授权码、授权码提示、快捷键。

行为说明：

- 装在 `你选的位置\CAScreenGuard-<日期>\`。同名目录已存在则拒绝安装。
- 本机已经装过时，运行新版安装器会先问一句，然后**就地升级**：只替换程序文件，
  解锁密码、授权码、提示、快捷键、桌面快捷方式和两处凭据全部原样保留，配置文件一个字节都不写。
  升级前会把旧程序文件和两棵注册表键备份到安装目录下的 `backup-<时间戳>\`。
  目录缺失、不像本程序的安装、找不到配置、程序正在运行这四种情况会说明原因后停止，不做任何修改。
- 桌面快捷方式带全局快捷键 `Ctrl + Alt + <字母/数字>`（写在快捷方式自身的「快捷键」字段里，
  不需要常驻进程，也不加开机自启）。
- 注册到「应用和功能」，发布者 `Conste11ation117`。卸载会删除注册表、外部凭证、桌面快捷方式
  以及整个安装目录。
- 装到没有写权限的位置（例如 `C:\Program Files`）时，会给出完整失败原因（异常类型与 `HResult`，
  可选中复制），并提供「以管理员身份重试」：UAC 通过后由提权助手建目录、把写权限授给你当前账户，
  然后继续安装。密码与授权码不经过命令行；装完的文件归你所有，之后写配置、写日志、卸载都不需要再提权。
- 通过 `conhost --headless` 启动，双击不会闪控制台窗口。
- 安装时选的语言写进外部凭证，装好的程序按它显示。

杀毒软件：实测 360 会提示但不判定为病毒，Windows Defender 放行。信任本软件的话建议加入白名单，
否则安装或运行可能被拦。

```

  CAScreenGuard.ps1        主脚本（带注释）
  ScreenLockEarly.cs       DPI 感知、隐藏控制台
  ScreenLockNative.cs      关屏、键盘钩子、置顶、空闲计时、唤醒请求
  Installer.cs             安装器
  assets/                  图标与字标图片
  bridge/                  给其它 harness 用的接入脚本
dist/    构建产物（不要手改）
  CAScreenGuard.ps1        去注释后的发布版主脚本
  CAScreenGuard-Setup.exe  安装器
tools/   构建与生成脚本
  build-setup.ps1  make-icon.ps1  make-wordmark.ps1
docs/    文档与截图
```

运行时需要四份文件放在同一目录：`CAScreenGuard.ps1`、`ScreenLockEarly.cs`、`ScreenLockNative.cs`、
`CAScreenGuard.ico`。脚本启动时用 `Add-Type -Path` 加载那两个 `.cs`，缺任何一个会提示文件不完整并退出，
所以不要只把 `.ps1` 单独拷走。

`dist/CAScreenGuard.ps1` 是 `src/CAScreenGuard.ps1` 的生成物，不要直接改。

## 十、开发与自检

```powershell
powershell -File tools\build-setup.ps1
powershell -File src\CAScreenGuard.ps1 -SelfTest
```

构建脚本做四件事：用 PowerShell 语法树去掉主脚本的注释与空行（字符串里的 `#` 不受影响）生成
`dist\CAScreenGuard.ps1`；去掉两个 `.cs` 的注释并先编译一遍确认没删坏；归一化源文件的 BOM 与行尾；
把四份文件嵌进安装器编译成 `dist\CAScreenGuard-Setup.exe`。

自检 8 项，不会关屏：配置文件读写、错误密码不接受、配置完整性判定（正常/被改/被删）、遮罩尺寸、
界面构建、空闲计时接口、错误密码处理、正确密码解锁。

`.ps1` 与 `.cs` 必须是 UTF-8 BOM 加 CRLF，否则中文会按 ANSI 解码变成乱码。

新增受版本控制的文件时，必须同时加进 `.github/workflows/release.yml` 的 `FILES` 清单，
否则发版 CI 会在打包清单校验一步失败。

## 十一、命令行参数

| 参数 | 说明 |
|---|---|
| `-ResetPassword` | 直接打开「修改解锁密码」（需授权码，这一次不熄屏） |

## 十二、关于防破解

脚本里没有可破解的秘密：解锁密码只以 PBKDF2 哈希存在，摘要密钥在外部凭证里，
把脚本从头读到尾既拿不到密码，也拿不到绕过校验的钥匙。

去注释、混淆、打包成 exe 都不会提高安全性：释放出的 `.ps1` 仍在磁盘上，
.NET 的 IL 反编译比读脚本更容易。根本原因是能改这个程序的人就能绕过它——换掉脚本或直接结束进程。
任何用户态遮挡程序都是如此。

真正能提高门槛的是：收紧安装目录的 ACL、别把密码写在便签或提示里、需要保密时用 `Win+L` 加 BitLocker、
使用受控账户。

## 十三、已知边界

- 同账户的攻击者若把注册表键和 `%APPDATA%` 那份凭据一起清掉，会退化成「从来没装过」：
  程序拒绝开锁并要求重新安装。这是失败安全，但原配置也就用不了了。
- 所有输入框禁用中文输入法，密码与授权码只收半角字符。
- 遮罩覆盖整块虚拟桌面（多显示器一起盖）。
- 锁屏期间系统保持唤醒，笔记本上比较费电。
- 不覆盖的情况：能改程序文件的人，或能用别的方式结束进程的人（另一个账户、把盘挂到别的机器上）。
  标记文件只能事后告诉你发生过。
